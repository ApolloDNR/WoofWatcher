## 0. TL;DR

- **What this repo is:** WoofWatcher — a premium, mobile-first dog-care app that
  plays like a living Tamagotchi. Real care logging (meals, walks, potty, meds)
  drives a pixel-art dog living in a room, XP/levels, trends, records, and a
  shareable care record. Tagline: *Real care. Pixel heart.*

  `artifacts/woofwatcher-mobile`. The web app in `artifacts/woofwatcher` is a
  secondary prototype — do not treat it as the product.

  forest-green, chunky pixel meters, storybook cards). They are now locked as
  canonical in `docs/design/APOLLO_MASTER_VISION_PROMPT.md`. When any older doc
  conflicts with those boards, the boards win.
- **What was just done (this session):** every screen restyled to those boards,
  a shared game-feel motion system added, and a new Care Sense meters card on
  Home. All work is on branch **`claude/mockup-parity-polish`** (3 commits).
- **Health of the branch:** `pnpm run typecheck` clean, `pnpm run test:focused`
  = **711/711 green**, Expo web export builds, headless screenshots + real
  interaction flows verified with **zero console errors**. Verified on the web

- **Update (later this session):** the four standalone board screens that were

## 2. What changed this session (the mockup-parity work)

Three commits on `claude/mockup-parity-polish`:

1. **Foundation** — palette + motion kit + chrome.
2. **Per-screen parity** — Log, Plan, Health, Records, Pack, Story, More, Studio.
3. **Home dedupe + canon** — one Care Sense meters surface; vision doc locked.

### 2.1 Design tokens — `constants/colors.ts`
- Parchment page `#F7F1E1`, card `#FDF9EE`, deep forest primary `#33582F`.
- Added **Care Sense meter tones** (sampled from the boards): `meterMood`
  `#3D6C33`, `meterEnergy` `#3D6C33`, `meterHunger` `#DE7A14`, `meterAlone`
  `#4E9CC7`, `meterSleep` `#6B4E93`, plus `gold` `#BC833D`.
- `pixelUi.statusSegments` changed **10 -> 7** (boards draw 7 chunky pips).
- Dark theme has matching meter tones; **dark mode is native-only** by design
  (`hooks/useColors.ts`), so it has NOT been visually audited — see §4.

### 2.2 Motion system — `components/motion/GameFeel.tsx` (NEW, the one motion language)
Everything animated should go through this. Exports:
- `SPRING` (default / pop / gentle), `MOTION_MS`, `enterUp(index)` staggered
  card entrance.
- `PressScale` — springy press wrapper (squish to 0.96, spring back, optional
  haptic). Note the `containerStyle` vs `style` split: layout (width/flex) goes
  on `containerStyle` (outer Pressable), visuals on `style` (inner animated
  view). Getting this wrong breaks grid widths.
- `MeterPip` — one Care Sense pip; pops on fill, staggers L->R, only animates
  when its filled state actually changes (honest motion).
- `useBounce` — 1 -> 1.12 -> 1 pop for icon buttons (the paw FAB uses it).
- `ProgressFill` — spring-settling progress bar (weekly goal, XP bars).
- All are `useReducedMotion()`-aware.

### 2.3 Shared primitives — `components/board/BoardPrimitives.tsx`
- `StatusMeter` now renders `MeterPip`s (7, animated) instead of static bars.
- `QuickActionTile` and `BoardActionButton` are springy (`PressScale`).
- `BoardCard` gained an `enter?: number` prop for staggered entrances.
- Kickers quieted to the board style: sage, `Inter_700Bold`, 9px, uppercase,
  letterSpacing 1.1 (no more shouty orange caps).

### 2.4 Home — `app/(tabs)/index.tsx`
- **Care Sense card** is the signature surface: headline glance line + 4 pip
  meters (Mood / Energy / Hunger / Alone). Every fill is derived from **real
  logged care** — mood word, `status.energy`, `meals.done/target`, and an
  open alone-session ratio. The old mood card + recency chips + the duplicate
  Happiness/Energy/Hunger status-tile grid were all folded into this ONE
  surface (the boards show one meter cluster, not two).
- **Quick Log card**: Meal / Potty / Walk / Meds + a real **More** tile that
  opens the fast-log sheet (Water, Note, etc. live there).
- **Care Status** card slimmed to the **Bond** meter + a **Diet profile** row
  (the only things Care Sense doesn't already show).
- Next Up, Today's Story, presence panel, living room, mission deck: preserved.

## 3. The rules to hold (non-negotiable — from the vision doc)

These are why the app feels trustworthy. Do not trade them for visuals:
1. **Every number is real.** XP, levels, streaks, meters, counts, statuses —
   all derived from real logged care. No coins, no fake badges/counts, no dead
   buttons. Undo takes the XP back.
2. **One meters surface on Home** (Care Sense). Don't reintroduce a second
   duplicate meter/tile cluster.
3. **Care workflows are sacred:** meal served->outcome lifecycle, potty flow,
   Health/Bile Watch **non-diagnostic** language, Records, Care Pass, privacy
   gates, and the test suite. Extend them; don't gut them for looks.
4. **The dog is alive** (animated sprite over a full-screen room that tracks the
   real clock — day 6am–8pm, night 8pm–6am). Consoles float; nothing touches the
   screen edge on native.
5. **Motion = one language** (`GameFeel.tsx`), crisp and consistent, reduced-
   motion aware. Motion presents real state; it never fakes progress.
6. **Don't claim provider features that aren't configured** (cloud sync, push,
   payments, store submission) unless the setup actually exists.

## 5. Getting this branch onto GitHub / into your next tool

The work is committed on `claude/mockup-parity-polish`. It was NOT pushed from
the Cowork cloud session (that sandbox's network blocked GitHub *write* and the
external host). To land it, from a machine with push rights to
`ApolloDNR/woofwatcher`:

**If you have the git bundle** (`woofwatcher-mockup-parity.bundle`):
```bash
git clone https://github.com/ApolloDNR/woofwatcher.git
cd woofwatcher
git fetch /path/to/woofwatcher-mockup-parity.bundle 'claude/mockup-parity-polish:claude/mockup-parity-polish'
git push -u origin claude/mockup-parity-polish   # then open a PR into main
```

**If you have the patch files** (`0001-*.patch … 0003-*.patch`):
```bash
git checkout -b claude/mockup-parity-polish origin/main
git am /path/to/patches/*.patch
git push -u origin claude/mockup-parity-polish
```

Then open a PR `claude/mockup-parity-polish -> main`, let CI run, review, merge.

> Note for a coding agent running in Apollo's own environment (Codex, etc.):
> you have his GitHub auth, so you can do the push above directly. Verify
> `pnpm run test:focused` on **Node 24** before pushing.
