## 1. What matters most in the new code

- `components/DayTrailScene.tsx` — Story hero. Painted map is the stage; the
  live layer (waypoints from today's real logs, the twin, the day-phase wash)
  must never invent data. `components/DayPhaseWash.tsx` is shared with the
  Adventure hero.
- `public/sw.js` + `scripts/smoke-web-export.js` — the export post-processor
  injects PWA tags, SW registration, and bakes the hashed bundle into the
  SW precache (cache version = bundle hash). Offline boot is verified.
- `docs/release/tools/store-pack.mjs` — one-command store screenshot pack
  (captures, seeds via the app's own tiles, clock-shifts to 10 AM, composes
  panels in-browser with real fonts).
- `context/CareContext.tsx` — hardened per the data audit: recovery-key
  backup before any cache reset, read-rejection pauses persistence instead of
  clobbering, persist failures surface via `storageWarning` (amber alert on
  Home), erase-generation guards on every post-await write path, pristine
  default docs carry an epoch `updatedAt` so they can never win
  reconciliation.

## 2. Deferred data-audit findings (next engineering queue)

A full adversarial audit of the persistence/sync layer confirmed more issues
than were initially fixed. Fixed as of the latest commits: silent
corrupt-cache reset, read-failure clobber, silent save failures,
wipe-resurrection paths, pristine-doc reconciliation, avatar transient-error
pruning, the setState-updater side effects (`updateEntry`/`deleteEntry`/
`updateCareDoc` now compute outside their updaters, refs chained eagerly),
the `pushDoc` 409 stale-snapshot clobber (replays `docRef.current` now),
durable record attachments (copied to
`documentDirectory/woofwatcher-attachments/`), and the owner wipe now also
deletes `WoofWatcherReports/` + the attachments directory. Care-entry creates are now **idempotent end to end** (client stamps
`details.clientKey`, server dedupes + a partial unique index backstops the
race — migration 0003, applied to the live Supabase project — and the merge
supersedes temp rows by clientKey). **Still open, in priority order:**

1. **Wipe-while-signed-in semantics are undefined** once Clerk is live
   (device wipe vs household wipe vs leave-household). Product decision for
   Apollo before sync launches; the privacy screen copy assumes local-only.
2. ~~Legacy PWA `woofwatcher.v1.state` import~~ **DONE 2026-07-19**: boot
   now adopts the legacy web app's saved data into a pristine v2 store
   (`lib/legacyImport.ts` + CareContext hydrate). Factory demo data is
   filtered, legacy Private logs keep `householdVisible:false`, the source
   key stays as backup, the owner wipe still removes everything, and Home
   shows a one-time welcome-back toast. Proven 11/11 by a Playwright probe
   (adoption, privacy, no double-import on reload) + 5 converter unit tests.
