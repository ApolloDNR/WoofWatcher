## 1. What "launch floor" means

The merged floor is the app that PR #7 describes: audited design/craft, full
WCAG dark-mode contrast, one motion vocabulary with Reduce Motion honored,
accessibility (VoiceOver/TalkBack via `lib/announce.ts`, aria semantics),
data-safety guarantees (legacy PWA import, erase-generation checks, idempotent
creates, honest `storageWarning`), and the redesigned Navigation / Log split /
Plan pickers+calendar / Story recap / Travel bag / More screens.

Remaining launch blockers are all **owner-gated**, not code:
App Store / Play Console accounts, legal blanks in `docs/legal/*`,
privacy-policy hosting, on-device QA, and — only if cloud sync / push / a paid
tier are ever turned on — provider setup (Clerk, database, APNs/FCM, billing).
v1 ships **local-first** without any of those. See
`docs/release/GO_LIVE_CHECKLIST.md`.

## 2. Branch consolidation — decision and reasoning (2026-07-29)

For ~2 weeks, three AI tooling lines edited the same app in parallel on
separate branches, none merged. Apollo chose: **land the verified branch as the
launch floor, then harvest the good pieces from the codex work.** The harvest
was reviewed subsystem by subsystem. Findings:

**The six diverged branches collapse to three real efforts:**

1. **`claude/session-…` (PR #7)** — the merged floor. Verified.
2. **`codex/woofwatcher-finish`** — the codex tip. Already contains
   `codex/woofwatcher-premium-renovation`, `feature/premium-navigation`, and
   the account-deletion code; the other codex/feature/recovery branches are
   older snapshots of it and can be ignored. Scope vs `main`:
   ~285 code files, +58k/−9.5k, ~40 new test files.
3. **`automation/premium-revenue-product-builder`** — a long-running Codex
   loop (~900 commits) with a tiny code footprint (~22 files): dark-mode
   contrast micro-tweaks + heavy doc churn. **This is the loop burning usage.**
   It runs outside this repo's control (Apollo's Codex/ChatGPT surface) and
   should be stopped there.

**Why `codex/woofwatcher-finish` was NOT harvested:**

It is not a parts bin — it is a *coherent, coupled parallel rebuild* of the same
app plus a cloud backend. Concretely:

- Its 48 new tested libs (`careDocMerge`, `careEntryMutationQueue`,
  `carePendingDeletes`, `careStorageScope`, `quickLogRuntime`, `appNavigation`,
  …) are **wired into rewritten screens** (e.g. its `log.tsx` imports
  `useQuickLogController`/`QuickLogGrid`). The libs are dead code without the
  screen rewrites, and the screen rewrites **compete with the verified floor**.
  Adopting them = swapping verified screens + a verified data-safety layer for
  an unverified parallel implementation. That is the fork Apollo declined.
- Its backend (api-server account-deletion / care-state / care-entry-history,
  `lib/db` schema, `lib/api-zod` types, `household-access` `inviteCode` →
  `canManageInvitations`) is **cloud/owner-gated** and not part of local-first
  v1. On-device "delete my data" already exists in the floor's owner-wipe flow;
  Apple/Google in-app account deletion only applies once real accounts exist.
- Its `lib/care-domain` src changes are cosmetic churn plus one product-identity
  reversal: `DEFAULT_PET_DISPLAY_NAME "Phoenix" → "Your dog"`. **"Phoenix" is a
  deliberate design choice** (the default care-twin persona — LivingPhoenixRoom,
  `phoenix-avatar.png`; setup.tsx uses it only as a placeholder hint). This is
  the automation loop stripping the app's personality, not a fix.

There is **zero name-collision** between codex/finish's new files and the floor,
so nothing was at risk; the point is that a clean *add* of those files buys
nothing without also taking the coupled screen/backend rewrites.

**Net:** the floor already contains the launch-grade version of everything
codex/finish reimplements. The only genuinely distinct asset is the **cloud
account-deletion backend**, which becomes relevant only at the (owner-gated)
cloud milestone. Preserve `codex/woofwatcher-finish` as the reference for that
work; do not merge it into a local-first v1.
