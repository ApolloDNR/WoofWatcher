# PixelLab Phase 1 Prompt - Phoenix Identity Lock

Use after PixelLab MCP verification only.

```text
Use the PixelLab MCP to begin WoofWatcher Phoenix Asset Production - Phase 1 only.

Do not generate rooms, accessories, or the full animation pack yet.

GOAL:
Create and lock one premium seated Phoenix care-twin identity in the Neo Retro Digital Pet style.

This is the main app avatar, not a tiny RPG directional sprite.

REFERENCE:
Use the approved WoofWatcher pixel-art references in:
docs/design/reference/

If those references are not present, stop and ask Apollo to upload them.

Primary visual target:
docs/design/reference/woofwatcher-pixel-reference-board-05-neo-retro-digital-pet.png

Secondary ecosystem target:
docs/design/reference/woofwatcher-pixel-reference-board-06-ecosystem-supporting-pages.png

Board 06 shows the full production family this identity must support: sleepy/resting Phoenix, WoofGuide side avatar, dark-mode room Phoenix, badge/logo head, achievement/bond art, and running footer sprite. The Phase 1 output is still one main identity, but it must look like it can become that whole family.

PHOENIX IDENTITY:
- adult female German Shepherd / Belgian Shepherd mix
- athletic medium-large quadruped body
- tall upright shepherd ears
- long intelligent muzzle
- black-and-tan saddle coat
- dark facial mask
- warm tan chest and legs
- full shepherd tail
- sage-green bandana
- dark collar
- small copper heart collar tag
- warm, loyal, intelligent, playful expression
- never wolf-like, puppy-like, aggressive, or humanoid

STYLE:
- premium neo-retro pixel art
- polished modern 32-bit-inspired digital pet character
- looks like the seated Phoenix in the Neo Retro Digital Pet mockup
- larger expressive avatar proportions, not a tiny RPG map sprite
- seated or calm standing pose for the main Home room
- clear face, eyes, ears, chest, bandana, collar, and tag at phone size
- rich black-and-tan shepherd markings with clean, deliberate pixel clusters
- transparent background
- no anti-aliasing or blur
- consistent palette
- readable at mobile-app size
- no room or props baked into the sprite
- looks ready to become the board 06 supporting-page asset family without changing identity

NEGATIVE TARGET:
- do not create a small 80-96px RPG directional dog as the primary identity
- do not create a flat golden cartoon dog
- do not create a compressed chibi dog with weak proportions
- do not remove Phoenix's black saddle, dark mask, bandana, collar, or copper heart tag
- do not create a generic RPG pet that only works on a tiny map grid

PROCESS:
1. Inspect the PixelLab MCP character and reference-image tools.
2. Create no more than four Phoenix main-avatar identity candidates.
3. Prefer reference-conditioned or style-reference generation where available.
4. Use identical canvas size, palette, lighting, scale, and direction.
5. Target a main avatar canvas suitable for app hero use, ideally 256px or 384px square if supported.
6. Save candidates into:
   artifacts/woofwatcher-mobile/assets/avatar/phoenix/candidates/
7. Create a contact sheet preview.
8. Document tool, settings, prompt, size, direction count, generation ID, and cost for every candidate.
9. Do not continue to animation.
10. Stop for human approval.

SUCCESS CRITERIA:
- Looks like the larger seated Phoenix in board 05.
- Belongs naturally beside the sleeping, WoofGuide, dark-mode, badge, and running Phoenix examples in board 06.
- Strong likeness to the approved reference.
- Transparent PNG.
- No cropped ears, paws, or tail.
- Clean pixel clusters.
- Bandana, collar, and heart tag consistent.
- Suitable for later idle breathing, tail wag, blink, sleep, anxious, proud, and home-alone animations.
- Directional walking sprites are a later derivative asset, not the Phase 1 success condition.
```
